# MONSOONAI — Phase 4 Completion Report (Streamlit Dashboard)

**Date:** 9 November 2026
**Status:** Built and tested locally. **Deployment: NOT done** (local only, by
instruction — Phase 6, on Harsh's approval, verified live before claimed).
**Models:** Linear Regression + Random Forest only. No XGBoost, no LSTM,
no unsupported features added.

## What was built

A six-page Streamlit dashboard under `app/`, in the project's deep
navy / atmospheric blue / restrained cyan design. Every navigation item
works; there are no decorative dead buttons. Every page carries the
data-category legend (historical reanalysis / observational data /
model prediction / external forecast) and the footer attribution
("Weather data by Open-Meteo.com (CC BY 4.0) … All model metrics are
performance against Open-Meteo / ERA5 reanalysis, not independent
rain-gauge observations").

| Page | Contents |
|---|---|
| 1. Overview | Mumbai rainfall intelligence + project summary; headline results; what the project does / does not do |
| 2. Rainfall Prediction | Next-day (t+1) prediction only, model selection (RF / LR / persistence / climatology), rain + heavy-rain probabilities, cutoff 23:59 Asia/Kolkata, input window t−7…t, data-availability info, archive freshness check, historical test-prediction explorer |
| 3. Historical Analysis | Annual/monthly trends, monsoon share 94.2%, rainfall distribution, exhaustive three-way classification (dry 5,468 / light 893 / rainy 2,771 = 9,132 days) |
| 4. Extreme Rainfall | Heavy-rain classifier metrics prominent (precision 0.137, recall 0.667, 88 false alarms, F1 0.228), thresholded regression results (LR 0/21, RF 2/21, persistence 6/21), worst misses, explicit "NOT suitable for operational warnings" statement |
| 5. Model Performance | Baselines + regression metrics (overall and rainy-day-only), classification metrics + confusion matrices, year-wise results, error by month, residual plots, feature importance (rain_t = 64% of RF signal), the honest reading (RF beats persistence on MAE by only 0.9%) |
| 6. Data & Methodology | Sources + licences, spatial/temporal alignment (r = 0.704 same-date, 0.741 shifted; IMD 3,553 mm vs Open-Meteo 2,774 mm in 2020, ~22% underestimation), resolution, reanalysis limitations, 27 feature definitions, leakage audit (no FAILs), models, reproducibility (seed 42) |

## How the dashboard gets its numbers (no drift possible)

- Regression metrics are **recomputed at startup from
  `artifacts/predictions_test.csv`** with the same logic as
  `src/evaluate_models.py` (full precision — this was necessary: the
  summary JSON stores metrics rounded to 4 decimals, which mis-rounds
  the Random Forest RMSE display, 11.3675 → 11.367 instead of 11.368;
  recomputing reproduces the report exactly, verified to 4 decimals
  against the JSON for all 16 values).
- Classification metrics, feature importances and year-wise results
  are recomputed from the saved joblib artefacts at startup.
- Predictions are generated by the saved artefacts from the local
  processed dataset, using only data dated t or earlier (the feature
  row for the latest date is built with the Phase 3 feature code —
  `src/features.py` is reused, not duplicated; verified: the on-the-fly
  prediction for cutoff 2021-07-08 is 14.45 mm, exactly matching the
  saved test prediction 14.447 mm).
- The `views/` folder is deliberately **not** named `pages/`, and
  `client.showSidebarNavigation = false` is set, so Streamlit does not
  inject its own multipage navigation above the app's navigation.

**Error handling — verified:**
- Missing artefact test: with `artifacts/random_forest_regressor.joblib`
  temporarily renamed, the app shows "MONSOONAI could not start —
  required data or model files are missing" with the missing path,
  and does not invent a substitute. Artefact restored afterwards.

  error and no invented value (code path tested via the same handler).
- Archive freshness button: clicked live — reports "Open-Meteo archive
  now reaches 2025-12-31; this build uses data through 2024-12-31"
  and does not auto-refresh.

**Bugs found and fixed during testing:**
1. IMD comparison CSV's first column has an empty header — the loader
   now renames it to `time` explicitly (was: app failed to start with
   "Missing column provided to 'parse_dates': 'time'").
2. `use_container_width=True` is deprecated in Streamlit 1.67 —
   replaced with `width="stretch"`.
3. Streamlit auto-discovered `app/pages/` as multipage navigation and
   injected a second nav above the app's own — folder renamed to
   `app/views/` and `showSidebarNavigation = false` set.
4. `**bold**` inside the HTML warning/info boxes rendered literally —
   fixed centrally in `ui_common.py`.
5. Metric delta text truncated with "…" and misleading ↑ arrows —
   deltas shortened and the arrow icon hidden by CSS.
6. The feature row for the latest cutoff day needed a dummy t+1 row;
   the first attempt broke pandas dtypes (`pd.NA`) and the second was
   dropped for a NaN target — fixed with a NaN copy of the last row
   with `precipitation_sum = 0.0` (that value only becomes the
   discarded target; no feature of t uses t+1 data).
7. `predictions_test.csv` is stored by **cutoff day t**, not by
   predicted day — the test-prediction explorer labels were corrected
   (the observed value shown is for t+1).

## Remaining limitations (honest list)

- **Deployment: NOT done.** Nothing is hosted anywhere. Streamlit
  Community Cloud deployment is Phase 6, on approval.
- **Data ends 31 Dec 2024.** The Open-Meteo archive now reaches
  2025-12-31 (checked live during testing) — refreshing requires
  re-running the Phase 2 pipeline and re-training; the dashboard
  reports this but does not auto-refresh.
- **No live weather.** The app reads the local dataset only; the
  "latest" prediction (for 2025-01-01) is a historical-data
  demonstration, labelled as such on the page.
- **Heavy-rain prediction remains unreliable** (see the Extreme
  Rainfall page) — the dashboard shows this; it does not fix it.
- **First load takes ~6 seconds** (model artefacts loading) — a
  spinner is shown; subsequent page switches are fast.
- **Streamlit's file watcher does not reliably reload the dynamically
  imported page modules (`views/`)** — after editing a page module,
  restart the server (`streamlit run app/app.py`).
- **Mobile:** the layout is responsive and verified at 390 px, but
  the desktop view is the primary one; the sidebar starts collapsed
  on mobile and must be opened to navigate.
- **Playwright's Chromium download** (`playwright install chromium`,
  headless shell) is installed in the venv for screenshots; the
  `--with-deps` system-package step was not completed (apt was slow)
  and was not needed — the headless shell runs without it.
